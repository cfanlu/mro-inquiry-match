# Excel / CSV 询价匹配输出规范

默认导出 `.xlsx`，采用已确认的“原始询价父行 + 候选商品子行”结构。用户指定其他模板时按其模板执行。CSV 使用文末的降级规则。

## 工作表和列顺序

主工作表命名为“选型匹配结果”，列顺序固定为：

| 顺序 | 列名 | 含义 |
| --- | --- | --- |
| 1 | 产品名称 | 客户明确提供的名称，或子行的数据源商品名称。 |
| 2 | 描述 | 客户原始描述，或子行的数据源商品描述。 |
| 3 | 规格型号 | 父行填客户型号或规格；子行沿用原结果的订货号字段，取 `productCode`，展示列名统一为“规格型号”。 |
| 4 | 品牌 | 父行填客户品牌；子行填数据源品牌。 |
| 5 | 制造商编号 | 制造商编号 / MPN，子行取 `mpn`；不与订货号、客户零件编码互相替代。 |
| 6 | 单位 | 父行的询价单位，或子行明确记录的数据源计价单位。 |
| 7 | 数量 | 父行的询价数量；子行没有相应明确数据时留空。 |
| 8 | 单价 | 有效数值单价。展示标题只写“单价”，不写“人民币单价”；API 内部仍读取 `priceCny`，不改变其字段名或计价口径。 |
| 9 | 匹配状态 | 子行自己的精确匹配、替代推荐、待确认或未找到结论。 |
| 10 | 数据源平台 | 该候选实际来源，例如西域、万物集、米思米或“我的商品（mine）”。 |
| 11 | 商品详情页链接 | 该候选实际返回的有效 `productPageUrl`。 |
| 12 | 匹配依据 | 对该候选已核实的规格、证据及原表首选/备选顺序。 |
| 13 | 待确认事项 | 缺失证据、差异、未知价格、链接缺失及其他需要确认的事项。 |

列名“规格型号”是本输出模板对原“订货号”列的展示约定；仍保留 `source + sourceId + productCode + mpn` 的对应关系，查询和判断时不得因此混淆这些字段。

原素材中其他与询价匹配有关的列，如客户零件编码、标准、材质、尺寸、备注、用途、图号、交期等，按原始顺序追加在上述固定列之后。保留其原列名和值，不能仅因信息已用于检索或写入匹配依据就丢弃该列。列名与固定列冲突时加“原始·”前缀区分。原“型号 / 描述 / 制造商编码”等已完整映射到固定列的字段不重复追加；需要合并多个来源列时，保留各原字段并避免覆盖或遗漏。

另保留完整原始询价工作表，作为追溯来源；不要用本次匹配结果覆盖原始单元格。重新排版历史匹配文件时，也保留历史原表并说明未重新查询。

## 父行：只展示客户原始需求

- 每条原始询价对应一条浅蓝底、加粗的父行，保持客户原始行顺序，包括重复询价和无结果行。检索可去重，输出必须还原每一行。
- 产品名称、描述、规格型号、品牌、制造商编号、单位、数量及末尾附加字段，均来自该行原始素材。原始空值保持空，不写“未指定”“未知”等替代文本，也不填入候选的品牌、型号或名称。
- 没有独立产品名称、只有一段混合描述时，“产品名称”留空，原文放在“描述”；不要自动拆解、翻译或用匹配商品名称补写原始名称。用于检索的解析结果另行维护。
- 制造商编号主要来自匹配结果。父行仅在原素材明确提供制造商编号时填写，不能把普通型号或客户自有编码自行认定为制造商编号。
- 父行的单价、匹配状态、平台、链接、匹配依据和待确认事项默认留空；这些结果写在下面的子行。原素材中已有的客户报价或备注等相关信息，保留为末尾原始附加列。

## 子行：每件候选独占一行

- 子行置于对应父行下面，最多首选 1 件加备选 5 件；每件商品的名称、描述、规格型号、制造商编号、品牌、计价单位、单价、链接和平台只使用该候选真实返回的信息。描述与名称是独立字段，缺失时留空。
- 获取完整展示资料时使用 `get_product(source, sourceId)` 补充列表响应未包含的描述、链接或计价单位。只为实际保留的候选获取详情；不要为填充展示字段重新进行匹配。
- 不将客户的单位、数量、品牌、描述或末尾附加信息复制到子行。源数据没有明确对应的数量时子行留空；库存、最小起订量和起订倍数不等于“数量”。
- 原素材附加列只在父行填原始值；不能将这些需求值写成候选已具备的属性。候选真实规格及差异写在匹配依据和待确认事项中。
- 每件候选单独判断状态，不能把父询价或首选的状态复制给所有备选。旧表只记录备选订货号而没有独立证据时保留已知资料，状态写“待确认”，说明还缺什么；不得编造缺失的名称、价格或平台。
- 首选仍按品牌、规格和匹配层级确定，在相同层级内按有效单价排序；便宜的替代项不能仅凭价格排在精确匹配项前。空价和 0 元视为无有效价格，展示留空并注明价格未知。
- 无合适商品时保留父行，下面写一条结果说明子行：状态为“未找到”，列出原因，其商品资料为空。该说明行不计为候选商品。
- Excel 中不再把多个备选挤在一个“其他匹配项”单元格中；最多 5 个其他匹配项分别成为子行。

## 链接、冻结和折叠

- 每件候选有有效 HTTP/HTTPS `productPageUrl` 时，“产品名称”显示原名称并设置单元格超链接，使用蓝色下划线；同时在“商品详情页链接”列保留可点击的完整地址。两处必须指向同一候选。不要将名称写成 URL 或公式，不自行拼接详情地址。
- 地址缺失时产品名称保留普通文本、链接列留空，在待确认事项注明“商品详情页链接缺失”；不因此改变规格匹配状态。私有商品没有外部地址时同样处理。
- 冻结 A:C 三列，即“产品名称、描述、规格型号”；D 列起可横向滚动。表头行一并冻结。例如表头在第 5 行、数据从第 6 行开始时，冻结位置为 `D6`；按实际表头位置调整，不能只冻结行或只冻结列。
- 使用 Excel 原生行分组 / 大纲功能，父行在上、子行在下，只将子行设为分组层级 1；默认展开。左侧有“＋ / −”，大纲“1”只看父行，“2”展开全部。颜色或缩进不能替代真正的行分组。
- 数据区不跨父子行合并单元格，不整表按价格或状态排序，不设置会打散父子关系的筛选排序。价格为数值并保留两位小数；数量保持原数值类型；长描述自动换行，字号清晰，列宽和行高避免裁切。

## CSV

仅在用户要求 CSV 时导出。使用相同字段顺序，将父行及子行依次展开为普通行；CSV 不支持冻结、分组、格式和带显示文本的超链接，需说明该限制。追加“记录类型”“原始行号”两列用于追溯父子关系，并将其他原始相关列保留在末尾；详情页链接仍为独立 URL 文本列。

## 导出检查

1. 父行数量与原始询价明细行数一致，原始工作表数据不变；不要要求含子行的结果总行数与输入相同。
2. 核对固定列名及顺序、末尾附加字段完整性；原始空值保持空，候选信息没有写进父行，客户需求没有误填成候选属性。
3. 检查每件商品的平台、规格型号、制造商编号、单价、链接和匹配结论属于同一 `source + sourceId`；保留逐项差异和无结果原因。
4. 核对前三列与表头冻结、summary-above 行分组、默认展开及各组边界；预览父行与子行的可读性。
5. 文件不包含 API Key。工具不能生成原生分组时明确说明限制，不声称已完成折叠。
